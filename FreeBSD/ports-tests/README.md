# FreeBSD ports regression tests

Hand-written smoke / regression tests for ports maintained by
`olivier@FreeBSD.org`. Run these after a port version bump (or before
committing) to make sure the new package still works end-to-end, not
just that it builds.

These are **not** automated by poudriere — invoke them manually on a
host where the rebuilt package is installed (`pkg install ...` or
`pkg add /usr/local/poudriere/data/packages/.../All/<port>.pkg`).

| `frr_pim_test.sh` | `net/frr10` (built with pimd) | 5-jail vnet PIM-SM lab, `start`/`check`/`stop`/`run`: `src` - `r1` (FHR) - `r2` (BSR-less static RP, on a loopback so reaching it exercises the unicast RPF lookup) - `r3` (LHR) - `rcv`, all links /24 with **static** unicast routing so a multicast failure is never a unicast failure in disguise. A python sender floods `239.60.1.1:5601` from behind r1; a python receiver behind r3 joins the group and counts what arrives. Asserts in two registers: FRR's view - (a) PIM adjacency, read from both ends of both links, (b) the static RP known by all three and claimed only by r2, (c) r3 learned the group from the IGMP report, (d) `(*,G)` upstream on the interface the route to the RP names, (e) the FHR holds `(S,G)` for the real source **and** the RP learned that source from a Register - and the kernel's, which is the half that cannot pass by accident: (f) an MFC entry in `netstat -g` on each router, (g) datagrams actually arriving at the receiver during a 10 s window. Sets `net.inet.ip.mcast.loop=0` (host global, not VNET-ized - a router otherwise loops every forwarded packet back into `ip_input()` and answers its own WRONGVIF upcalls; `stop` restores it). Twelve assertions, and **all of them pass on `frr10-10.7.1_7`** - which they did not when the lab was written: PIM-SM was broken on FreeBSD for four separate reasons, none of which a build or a `show` command surfaces, and the port now patches all four. (i) `pim_igmp_sock_add()` bound a raw IGMP socket with a `sockaddr_in` it never zeroed, and FreeBSD's `rip_bind()` compares every `sa_len` byte (`sa_equal()`), so `bind()` returned EADDRNOTAVAIL on a perfectly local address and pimd had no IGMP socket at all - `patch-pimd_pim__igmp.c`, one `memset`. (ii) FRR does not parse IGMP from those sockets anyway (`pim_igmp_read()` drains and discards); it parses what arrives on the *mroute* socket, and `pim_mroute_set()` asked for the ingress ifindex with `IP_PKTINFO` only, with no BSD `IP_RECVIF` branch - so `ifindex` stayed -1, `process_igmp_packet()` looked up interface -1 and dropped every report silently. (iii) the register vif was never created: `pimreg` is an internal pseudo-interface with no address (`pim_if_create_pimreg()`, hardcoded vif 0) and BSD adds vifs by local address, so `pim_mroute_add_vif()` refused it - lending it another PIM interface's address the way `net/pimd`'s `update_reg_vif()` does makes the kernel raise the `IGMPMSG_WHOLEPKT` upcall FRR already handles; and the Register then still left as **IP protocol 255**, because `pim_msg_send()` builds its own IP header while `pim_reg_sock()` uses `IPPROTO_RAW`, which implies `IP_HDRINCL` on Linux but not on BSD (`patch-pimd_pim__sock.c`). (iv) the stream then stopped one hop short of the receiver: FreeBSD's `mfc_find()` matches the source exactly (`in_hosteq()`), so there is no wildcard mfc - the `(*,G)` entry forwards nothing and the kernel raises a NOCACHE per source, where `pim_mroute_nocache_forward_existing()` returned early for want of an `(S,G)` upstream, the normal state on an LHR whose receivers joined `(*,G)` (Linux never asks: `ipmr_cache_find_any()` resolves it against the wildcard entry). Creating the `(S,G)` from the `(*,G)`, as the WHOLEPKT path already does for an LHR, is what finally delivered packets. And with traffic flowing the counters were still zero, because BSD gates `SIOCGETSGCNT` on `PRIV_NETINET_MROUTE` and pimd has dropped to `frr` - blind keepalive and SPT-switchover decisions, which break a stream minutes in, long after a short data-plane check passes; assertion (h) is there to catch exactly that. (ii), (iv) and the ioctl live in `patch-pimd_pim__mroute.c`. Verified by two cold `run`s and a 250 s soak past `keep_alive_time`. | `sudo`, vnet jails, root, VIMAGE, `ip_mroute.ko`, python3, `frr10` built with pimd |

## How to run

```sh
# net/sslh — fast smoke test
sh sslh.sh

# net/bird{2,3} — bring up vnet routing lab
sh bird_test.sh start
sudo jexec bird3 birdc -s /var/run/bird/bird3.ctl
# ...inspect routes / protocols...
sh bird_test.sh stop

# net/bird2 — multi-FIB host-only regression (no jails), both directions
sh bird_fib_test.sh start
sh bird_fib_test.sh check     # exits non-zero if either direction fails
sh bird_fib_test.sh stop

# net/frr{8,9,10} — same idea
sh frr_test.sh start
sh frr_test.sh stop

# net/pimd — PIM-SM multicast lab in vnet jails, now lives in the pimd tree
cd ~/pimd
sh test/freebsd-lab.sh run all            # rpt, keepalive and rp-lasthop scenarios
sh test/freebsd-lab.sh start rp-lasthop   # or drive one by hand
sudo jexec pimd_r3 ~/pimd/src/pimctl -u /tmp/pimd-test/r3.sock show mrt detail
sh test/freebsd-lab.sh check rp-lasthop   # logs kept in /tmp/pimd-test.*.failed on failure
sh test/freebsd-lab.sh stop               # also restores net.inet.ip.mcast.loop

# net/frr10 — PIM-SM multicast lab (needs frr10 built with pimd)
```

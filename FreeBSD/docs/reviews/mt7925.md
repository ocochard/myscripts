## Bugs

POSTCR-11d69a4558de2a5427d8191caed315c5f7e9a5d6-1 (pre-existing, from
11d69a4558de "LinuxKPI: 802.11: add support for suspend/resume"; the
last commit extends it to mt7925). `lkpi_80211_pm_attach()`
(linuxkpi_80211_pm.c:159) saves `pdev->pdrv->suspend`/`resume` in its
softc and replaces them with `lkpi_80211_pm_suspend`/`resume`. `pdrv`
is the driver's one static `struct pci_driver`, shared by every device
it drives. With two cards of the same driver, the second child saves
the already replaced pointer: suspending that card calls
`lkpi_80211_pm_suspend()`, which finds its child, suspends net80211,
then calls `sc->suspend`, itself, again, without end (stack overflow).
Detaching the first card restores `NULL` while the second child still
expects the hook. The same holds for iwlwifi. Fix: replace the pointers
once per driver (only when they are not already the hooks) and keep
the originals per driver, not per device; or hook in linux_pci.c.
Not reachable on the zbook (one card).

## Other comments

- Commit 1 puts `MODULE_DEPEND(mt7925_pci, lindebugfs, ...)` in
  mt7925/debugfs.c; mt7921 has its line in pci.c under
  `#if defined(CONFIG_MT7921_DEBUGFS)`. Both work (debugfs.c is built
  only with MT7925_DEBUGFS); matching mt7921 would keep the module glue
  in one place.
- Commits 2 and 3 add `mt79xx_init_done()` and its calls outside
  `#if defined(__FreeBSD__)`: on Linux they compile to an empty static
  function. bz keeps FreeBSD changes to contrib in `__FreeBSD__`
  blocks; putting `complete()` itself in such blocks at the three call
  sites keeps the vendor diff smaller. Checked: success completes in
  `mt76_register_device()` after `MT76_STATE_REGISTERED` is set
  (mac80211.c:823), every failure path before it now completes, and
  `linux_work_fn()` touches no part of the work item after the callback
  returns, so the probe error path may free `dev` once it wakes.
  mt7921 has no hardware to test here.
- Commit 4 removes `phy->debugfs_dir` in `mt76_unregister_phy()` and
  `mt76_unregister_device()` before `ieee80211_unregister_hw()`, while
  the file private data is still alive; the directory exists only after
  registration, which both functions require. Default builds have no
  debugfs (MT76_DEBUGFS ?= 0, MT7925_DEBUGFS = 0), so commits 1 and 4
  matter only for debugfs builds.
- Commit 5 builds `mt76_core` with CONFIG_PM. No mt76 header changes
  layout with CONFIG_PM, so mt7921 (built without it) still matches
  the core. Side effect: `mt792x_load_firmware()` now sets
  `wiphy->wowlan` for mt7921 too; LinuxKPI only uses WoWLAN with
  `compat.linuxkpi.80211.suspend_type` bit 2, off by default.
- The branch carries an older copy of the LinuxKPI commits: #125
  (pr/lkpi-mt7925) has review changes in them. The 5 mt76 commits
  replay onto pr/lkpi-mt7925 without conflict and with the same diffs
  (3b4175071e37 in the scratch worktree); all mt76 modules build there,
  default and with MT76_DEBUGFS=1 MT7925_DEBUGFS=1 MT7921_DEBUGFS=1,
  and if_mt7925.ko contains lkpi_mt7925_pm.o. That rebased series has
  not run on hardware.
